# Gameplay and scripted sequences

**This specification defines the foundational pattern for Exolune gameplay mechanics and scripted character sequences.** It separates pure gameplay state from rendering, skinning and review tools.

## State and rendering separation

- **Pure C++ state modules:** game rules, state machines and preconditions live in zero-D3D12 headers (`TransportEquipment.h`, `WalkController.h`, `Gameplay.h`).
- **Rendering isolation:** GPU skinning, shadows, ambient crowds and sequence playback remain in `Characters.cpp` and `CharacterSequences.cpp`.
- **No automatic demo loops:** in a generic launch, every scripted sequence starts `Dormant` with zero CPU animation work and zero hidden-actor draw cost.

## Scripted sequence lifecycle

- **Phases:** `Dormant -> Armed -> Running -> Completed` in `Gameplay::SequencePhase`.
- **Trigger path:** `D3DApp::TriggerSequence(Gameplay::SequenceId)` arms the sequence and resets its character actors without embedding game flow rules inside `Characters`.
- **Preconditions:** `Gameplay::Advance` holds `Armed` actors ready until runtime conditions match, then steps the sequence clock while conditions hold.
- **Completion:** `Gameplay::SyncProgress` transitions to `Completed` once all actors reach their end state, allowing one-shot HUD feedback via `TransportNotice`.

## Shuttle boarding (`shuttle_boarding`)

- **Manifest:** stored outside Git under `<character-bank>/sequences/shuttle_boarding.txt` (generated by [generate_boarding.py](../tools/characters/generate_boarding.py)), with fallback to `boarding.txt`.
- **Cast and path:** `pilot_explorer` and eight passengers stand on Pad 43, climb the deployed rear airstair when the shuttle hatch is open, take their cabin and cockpit seats in front-to-back order, and stay aboard in flight.
- **Triggers:** review routes activate it with the `sequence=shuttle_boarding` (or alias `embarquement`) token, and a temporary manual test key (`7`) can trigger it while parked beside or inside the V9 shuttle until a mission director replaces it.

## Generic launch integration

- **Profile configuration:** `MyPlanetEngine.ini` accepts an optional `[Monde]` section (`Ville`, `Personnages`, `Vaisseau`, `Camera`) applied by [Settings.cpp](../MyPlanetEngine/Settings.cpp) without overriding explicit environment variables.
- **Automatic discovery:** when no environment override is given, [D3DApp.cpp](../MyPlanetEngine/D3DApp.cpp) searches `assets\city\scene.bin` (or shared sibling `ville\scene.bin`) and `assets\characters\characters.bin` (or shared sibling `personnages\characters.bin`) via `FindAbove`.
- **Priority:** explicit `-Ville` / `-Personnages` launcher arguments and `MYPLANETENGINE_CITY_ASSETS` / `MYPLANETENGINE_CHARACTER_ASSETS` always override automatic discovery.
